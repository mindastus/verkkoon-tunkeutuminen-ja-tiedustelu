# x) Lue ja tiivistä

**Karvinen 2025: Wireshark - Getting Started**
- Wireshark on suosittu verkkoliikenteen analysointi- ja kaappausohjelma *(packet sniffer)*, jolla voidaan tarkastella verkossa liikkuvia paketteja.
- Kaapattu liikenne voidaan tallentaa .pcap-tiedostoon ja avata myöhemmin analysoitavaksi.
- Debianissa Wireshark asennetaan `apt-get install wireshark` -komennolla. Asennuksen yhteydessä kannattaa sallia myös tavallisten käyttäjien pakettikaappaus.

**Karvinen 2025: Network Interface Names on Linux**
- Verkkorajapinta *(network interface)* vastaa verkkokorttia, mutta se voi olla myös virtuaalinen. Kaikki rajapinnat eivät siis ole fyysisiä laitteita.
- Modernit Linux-jakelut käyttävät systemd:n nimeämiskäytäntöä, jossa verkkorajapintojen nimet kuvaavat niiden tyyppiä ja sijaintia.
- Nimen loppuosan numerot ilmaisevat yleensä laitteen sijainnin tai tunnisteen, minkä ansiosta sama verkkolaite saa yleensä saman nimen myös uudelleenkäynnistysten jälkeen.

**Kerrosten selitys**

<img width="864" height="347" alt="image" src="https://github.com/user-attachments/assets/293a47d3-e968-4cc9-ac6c-066693dcbd69" />

Kuvassa on Wiresharkilla siepattu HTTPS-liikenteeseen kuuluva paketti. TCP/IP-mallin verkkorajapintakerrosta vastaa Ethernet II, joka huolehtii kehysten siirtämisestä lähiverkossa. Internet-kerroksena toimii IPv4, joka vastaa pakettien reitityksestä verkkojen välillä. Kuljetuskerroksena näkyy TCP (Transmission Control Protocol), joka tarjoaa luotettavan tiedonsiirron yhteyden osapuolten välille. Sovelluskerroksella liikenne liittyy HTTP-protokollaan, joka kulkee tässä tapauksessa TLS-suojatun yhteyden sisällä. Näin paketista voidaan tunnistaa kaikki TCP/IP-mallin neljä kerrosta.

**Kaappauksen yleiskuvaus**

Tutustuin kaappaukseen pintapuolisesti Wiresharkissa. Kaappaus sisältää tavallista verkkoselaamisesta syntynyttä liikennettä. Liikennettä kulkee oman koneen, lähiverkon palvelimen tai reitittimen sekä useiden ulkoisten palvelimien välillä.

Kaappauksessa näkyy erityisesti seuraavia protokollia:
- DNS *(Domain Name System)*
- TCP *(Transmission Control Protocol)*
- TLS 1.3 *(salattu HTTPS-liikenne)*
- QUIC *(HTTP/3-yhteyksissä käytettävä protokolla)*

Kaappauksesta voidaan havaita, että selain tekee ensin DNS-kyselyitä esimerkiksi www.google.com ja terokarvinen.com, minkä jälkeen muodostetaan salattuja yhteyksiä verkkopalvelimille.

Kaappaus on melko pieni. Wiresharkin perusteella se sisältää 283 pakettia.

Yleisellä tasolla kaappaus näyttää normaalilta käyttäjän verkkoliikenteeltä. Suurin osa liikenteestä on salattua ja QUIC-liikennettä, mikä on tyypillistä nykyaikaisille HTTPS-sivustoille. Lisäksi kaappauksessa näkyy DNS-kyselyitä, TCP-yhteyksien muodostamista sekä selaimen ja verkkopalvelimien välistä tiedonsiirtoa.

Paketti 1: DNS-kysely
Source: 192.168.122.7
Destination: 192.168.122.1
Protocol: DNS
Info: Standard query A www.google.com


Tässä paketissa tietokoneeni (192.168.122.7) lähettää DNS-palvelimelle (192.168.122.1) kyselyn. DNS-järjestelmän tehtävänä on muuntaa verkkotunnukset IP-osoitteiksi. Selain ei voi muodostaa yhteyttä osoitteeseen "www.google.com" ennen kuin se tietää palvelimen IP-osoitteen.

Paketti kulkee UDP-protokollan sisällä porttiin 53, joka on DNS-palveluiden yleinen portti. Kyselyssä pyydetään A-tietuetta, eli IPv4-osoitetta verkkotunnukselle www.google.com.

Paketti 2: DNS-vastaus
Source: 192.168.122.1
Destination: 192.168.122.7
Protocol: DNS
Info: Standard query response


DNS-palvelin lähettää vastauksen takaisin tietokoneelleni. Vastauksessa kerrotaan palvelimen IP-osoite. Tämän tiedon avulla selain tietää, mihin palvelimeen yhteys täytyy muodostaa.

Ilman tätä vastausta selain ei pystyisi avaamaan verkkosivua, koska ihmisille helppolukuinen verkkotunnus täytyy ensin muuntaa koneiden käyttämäksi IP-osoitteeksi.

Yhteyden muodostaminen

Heti DNS-vastauksen jälkeen näkyy TCP- ja TLS-liikennettä.

TCP SYN
TCP SYN, ACK
TCP ACK


Nämä paketit muodostavat TCP:n niin sanotun three-way handshaken eli kolmivaiheisen kättelyn.

Selain lähettää SYN-paketin palvelimelle.
Palvelin vastaa SYN-ACK-paketilla.
Selain kuittaa yhteyden ACK-paketilla.

Tämän jälkeen TCP-yhteys on muodostettu.

TLS-salaus

TCP-yhteyden jälkeen näkyy:

TLSv1.3 Client Hello
TLSv1.3 Application Data


Client Hello on TLS-salauksen aloitusviesti. Selain kertoo palvelimelle, mitä salausasetuksia se tukee. Kun TLS-yhteys on muodostettu, varsinainen verkkoliikenne kulkee salattuna.
Tämän vuoksi Wiresharkissa ei voida lukea verkkosivun sisältöä suoraan, vaan näkyvissä on pääasiassa vain metatietoja, kuten IP-osoitteet, portit, pakettien koot ja käytettävät protokollat.


Kaapattu liikenne näyttää tavallisen verkkosivun avaamisen. Prosessi etenee seuraavasti:
- Selain pyytää DNS-palvelimelta verkkotunnuksen IP-osoitteen.
- DNS-palvelin palauttaa IP-osoitteen.
- Selain muodostaa TCP-yhteyden palvelimeen.
- TLS-salaus otetaan käyttöön.
- Verkkosivun sisältö siirtyy salattuna yhteyden yli.
